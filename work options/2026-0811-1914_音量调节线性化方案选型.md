# 音量调节线性化方案选型

> **状态**：草稿
> **范围**：音量控制链路（网页播放器 → QtWebEngine → 系统音频）
> **时间**：2026-08-11 19:14（设计）(UTC+8)
> **优先级**：中

---

## 1. 背景与约束

### 1.1 问题现象

音量滑块在 **10 以下时音量过小**，**10 以上又迅速增大**，听感明显非线性。用户难以在低音量区间做精细调节。

### 1.2 根因分析

本项目是网易云音乐网页端的 QtWebEngine 套壳应用，**音量完全由网页播放器内部控制**。网页播放器的滑块位置 → `audio.volume`（0~1 线性振幅）的映射本身采用了类似平方/立方的压缩曲线，导致：

- 低段（滑块 < 10%）：振幅被压到接近零，音量过小；
- 中高段：振幅随滑块快速上升，增长过陡。

人耳对响度的感知近似对数关系，叠加网页端自身的压缩曲线后，低段听感被进一步压缩。

### 1.3 现状代码

- `gui/main_window.py` 中仅有读取 localStorage 音量键的**诊断代码**（`verify_localstorage_and_volume` / `_check_localstorage_and_volume`），无任何音量干预逻辑。
- JS 注入方式现状：页面加载完成后通过 `runJavaScript` 执行（时机偏晚）。
- `tray_manager.py` 托盘菜单无音量控制项。
- `pipewire_manager.py` 仅管理 PipeWire 服务本身，未做应用级音量映射。

### 1.4 约束

- 不修改网易云网页端源码（无法修改，只能注入干预）。
- 不破坏网页播放器的 UI 一致性（音量条显示与实际状态不能脱节）。
- 干预逻辑必须可关闭、参数可调，便于实测调优。
- 遵循项目既有架构：GUI 层代码在 `gui/`，JS 注入经由 QtWebEngine。

## 2. 候选方案

### 方案 A：劫持 `HTMLMediaElement.prototype.volume`（注入补偿曲线）

在页面脚本运行**之前**，用 `Object.defineProperty` 重写 `HTMLMediaElement.prototype` 的 `volume` 属性存取器：

- **setter**：页面写入值 `v`（0~1）时，实际写入 `Math.pow(v, k)`，`k < 1` 抬高低段（`k=0.5` 即开平方补偿）。
- **getter**：返回逆变换值 `Math.pow(real, 1/k)`，保证网页 UI 读回的音量与其设定值一致，播放器无感知。

关键技术点：

- 注入时机必须用 `QWebEngineScript` 的 `DocumentCreation` 阶段（页面任何脚本运行之前），且注入世界必须为 `MainWorld`（与页面脚本共享原型链；`ApplicationWorld` 是隔离世界，拦截不到页面写入）。
- 现状 `runJavaScript` 注入时机太晚：播放器可能已缓存原生 setter 引用，劫持失效，**必须改为 `QWebEngineScript`**。
- 播放器内部曲线记为 `g(s)`（s 为滑块位置），我们拦截到的是 `g(s)` 的结果，补偿函数 `h(v)=v^k` 的实际效果是 `h(g(s))`。由于 `g` 未知，**k 需实测调优**，建议做成设置项（如 0.3~0.7 连续可调），不写死。

参考实现骨架：

```js
// gui/volume_compensation.js（新建，由 QWebEngineScript 加载）
(function() {
    'use strict';
    var K = 0.5;  // 补偿指数，< 1 抬高低段；待实测调优
    var proto = HTMLMediaElement.prototype;
    var desc = Object.getOwnPropertyDescriptor(proto, 'volume');
    var origSet = desc.set, origGet = desc.get;
    Object.defineProperty(proto, 'volume', {
        configurable: true,
        enumerable: desc.enumerable,
        get: function() {
            var real = origGet.call(this);
            return Math.min(1, Math.pow(real, 1 / K));  // 逆变换，保持 UI 一致
        },
        set: function(v) {
            v = Math.max(0, Math.min(1, v));
            origSet.call(this, Math.pow(v, K));          // 补偿后写入真实音量
        }
    });
})();
```

### 方案 B：自建音量 UI，绕过网页音量条

在托盘菜单 / 全局快捷键 / 标题栏增加应用自己的音量控制。Qt 侧按感知线性曲线计算目标振幅，直接通过 JS 写入 `audio.volume`，网页端音量条弃用。

- 曲线完全自定义，可做真正的等响度步进（如每档 +3 dB）。
- 通常需配合方案 A 锁定网页侧写入，或隐藏/忽略网页音量条，否则两边状态打架。

### 方案 C：Web Audio API 改道 GainNode

注入脚本将播放链改道：`AudioContext → MediaElementAudioSourceNode → GainNode → destination`，用 GainNode 做增益映射。

- 理论上最干净（增益节点天然支持任意映射），但网易云播放器直接操作 `<audio>` 元素，改路由易与其播放控制（切歌、暂停、换 URL、seek）冲突。

### 方案 D：系统层补偿（PipeWire）

在 `pipewire_manager.py` 层对应用音频流施加非线性增益映射。

## 3. 各方案优缺点

### 方案 A：prototype 劫持

| | |
|:---|:---|
| ✅ 优点 | 改动最小：一个 JS 文件 + `gui/main_window.py` 中注册 `QWebEngineScript`；不动网页 UI、不改播放器逻辑；getter 逆变换保证网页无感知；可关闭、参数可调 |
| ❌ 缺点 | 拦截的是播放器内部曲线 `g(s)` 的输出，`g` 未知，补偿指数 k 需实测调优；`MainWorld` 注入与页面共享世界，理论上存在被页面脚本覆盖原型的风险（需观察） |
| ⚠️ 风险 | 若网易云前端改为非 `<audio>` 播放（如 MSE + Web Audio），劫持失效——当前网页端为 `<audio>` 元素播放，风险低 |

### 方案 B：自建音量 UI

| | |
|:---|:---|
| ✅ 优点 | 曲线完全自主，可做精确等响度步进；与系统托盘/快捷键天然整合；不依赖对网页内部行为的假设 |
| ❌ 缺点 | 与网页音量条状态双轨，必须处理同步或取舍（隐藏网页条 / 单向锁定）；涉及托盘菜单、快捷键、设置持久化，工作量明显更大 |
| ⚠️ 风险 | 用户若在网页内拖音量条，自建 UI 显示即失真，体验割裂 |

### 方案 C：GainNode 改道

| | |
|:---|:---|
| ✅ 优点 | 增益映射能力最强，可在音频图内做任意处理（扩展空间如均衡器） |
| ❌ 缺点 | 侵入网页播放链路，与播放器状态机耦合，切歌/换源时易失效；调试成本高 |
| ⚠️ 风险 | 网易云前端升级即可能破坏，长期维护成本最高 |

### 方案 D：PipeWire 系统层

| | |
|:---|:---|
| ✅ 优点 | 完全不碰网页 |
| ❌ 缺点 | **不治本**：系统层看不到网页滑块位置，无法修正曲线形状，只能整体缩放；PipeWire 音量本身已接近感知线性，叠加非线性映射反而更乱 |
| ⚠️ 风险 | 与系统音量、其他应用的音量管理混淆，副作用不可控 |

## 5. 推荐结论

**推荐方案 A（prototype 劫持 + 补偿曲线），作为第一阶段实施。**

理由：

1. 直击根因——在振幅写入环节修正曲线形状，改动量最小，可快速验证听感；
2. getter 逆变换保证网页 UI 无感知，不引入状态双轨问题；
3. 补偿指数 k 做成可调参数，实测后收敛到合适的默认值。

**方案 B 作为可选的第二阶段**：若第一阶段后仍希望有托盘滑块、滚轮调音量等应用级控制，再叠加方案 B，并以其复用方案 A 的补偿映射。

方案 C、D 排除：C 维护成本与前端升级风险过高；D 无法修正曲线形状，治标不治本。

1. **新建注入脚本** `gui/volume_compensation.js`，k 初始值取 0.5（开平方补偿）。
2. **改造注入时机**：在 `gui/main_window.py` 的 web view 初始化处注册 `QWebEngineScript`，`InjectionPoint = DocumentCreation`，`WorldId = MainWorld`，替换现有"页面加载后 `runJavaScript`"的路径（仅针对本功能）。
3. **验证手段**：
   - JS 侧：注入后读取 `audio.volume` 写入/读回一致性（写入 0.1 应读到 0.1，底层真实值应为 ~0.316）；
   - 听感侧：滑块 5 / 10 / 30 / 50 档位对比补偿前后响度；
   - 日志：注入成功/失败写入现有日志体系（`logger/`）。
4. **参数化**：k 值先进 `profile_manager.py` 的配置项（如 `volume_compensation.k`），设置界面（`gui/settings_dialog.py`）的暴露可后置。
5. **回退设计**：配置项关闭时完全不注册该脚本，行为与现状一致。
