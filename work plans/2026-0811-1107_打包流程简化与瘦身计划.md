# 打包流程简化与瘦身计划

> 状态：已完成（2026-08-11 11:40）
> 范围：打包体系（`pack.py`、`packaging/`、PyInstaller spec、AppImage 产物）
> 时间：设计 2026-08-11 11:07 / 实施 2026-08-11 11:07-11:40
> 优先级：中
>
> 实施结果：AppImage 211 MiB → 178 MiB（-33 MiB，-16%）；入口收敛为
> `bash packaging/scripts/build_appimage.sh`；GUI 打包程序及 `pack.py` 已删除；
> 冒烟验证通过（窗口创建、网页加载、登录数据有效）。
> 实施中修正：① `SPECPATH` 是目录而非文件路径；② 清理语句误删 appimagetool
> （find 模式需排除 `appimagetool*`）；③ `PySide6.QtWebChannel` 被
> `QtWebEngineCore` 扩展运行时依赖，不能 exclude（已从排除清单移除）。

## 1. 背景与问题定位

### 1.1 现状

当前打包体系为"tkinter GUI + 5 个 shell 脚本"结构：

- `pack.py` 只是 GUI 启动器（`pack.py:52` 导入 `packaging/scripts/packaging_gui.py`）
- `packaging/scripts/packaging_gui.py`（448 行 tkinter）提供 5 种模式：快速构建 / AppImage 构建 / 依赖检查 / 测试构建 / 清理临时文件
- 实际构建逻辑在 `packaging/scripts/quick_build.sh` 与 `build_appimage.sh`（467 行）
- spec 文件在构建时临时生成于 `packaging/temp/`

### 1.2 已确认的事实

| 事实 | 证据 |
|---|---|
| 现有 AppImage 产物 211 MiB，明显偏大 | `packaging/dish/网易云音乐桌面版-x86_64.AppImage` 221,619,392 字节 |
| spec 的 hiddenimports 落后于代码，缺新模块 | `packaging/temp/NetEaseMusic.spec:22-37` 缺 `gui.title_bar`、`gui.window_resize`、`pipewire_manager_integration`（`main.py:20` 直接导入） |
| spec 硬编码绝对路径，不可移植 | `NetEaseMusic.spec:7` `project_root` 写死 |
| excludes 仅排除科学计算库，未碰 Qt/PySide6 冗余模块 | `NetEaseMusic.spec:40-48` |
| 双套产物名并存，逻辑分散 | quick 版 `NetEaseCloudMusic` / AppImage 版 `NetEaseMusicDesktop`，`test_build.sh` 测的是前者 |
| 文档存在过期引用 | `packaging/README_GUI.md`、`clean_temp_files.sh` 仍写旧目录名 `packaging_04/` |
| 构建缓存占地大 | `build/` 437M、`dist/` 214M |

### 1.3 改造目标

1. **去 GUI 化**：删除 tkinter 打包 GUI，收敛为**一个简单打包脚本**，命令行一键出包
2. **只出 AppImage**：废弃快速构建/测试构建等多模式，产物统一为 x86_64 AppImage
3. **瘦身**：精简打包内容，显著降低 AppImage 体积（目标：从 211 MiB 降到可实测的更低值，验收时以实测数据为准）

## 2. 改造思路总览

| 层面 | 现状 | 目标 |
|---|---|---|
| 入口 | `pack.py` → tkinter GUI → shell 脚本 | 单个 shell 脚本 `packaging/build_appimage.sh`（重写简化版），根目录 `pack.py` 删除或改为薄封装 |
| 构建模式 | 5 种模式 | 仅 AppImage 一种 |
| spec | 构建时临时生成、硬编码路径 | 持久化到 `packaging/NetEaseMusic.spec`，用 `SPECPATH` 相对定位 |
| 产物 | 双命名、双目录（`dist/` + `dish/`） | 统一命名，仅输出到 `packaging/dish/` |
| 体积 | 全量 PySide6 + 7 个图标 + 整体目录打包 | 排除未用 Qt 模块、裁剪 datas、UPX 压缩 |

## 3. 实施步骤

### 3.1 第一步：重写打包脚本（核心）

重写 `packaging/scripts/build_appimage.sh` 为简化版，流程固定为：

1. 检查 `.venv` 存在，使用项目 `.venv` 的 Python（遵循 AGENTS.md）
2. `pyinstaller packaging/NetEaseMusic.spec --clean --noconfirm --distpath packaging/temp/dist --workpath packaging/temp/build`
3. 组装 AppDir（可执行文件 + `.desktop` + 图标 + AppRun，沿用现有 `build_appimage.sh:264-309` 的成熟做法）
4. 调 `packaging/temp/appimagetool-x86_64.AppImage` 打成 AppImage（不存在则从 GitHub 下载，沿用现有逻辑）
5. 产物输出到 `packaging/dish/网易云音乐桌面版-x86_64.AppImage`
6. 构建结束清理中间产物（`packaging/temp/dist`、`packaging/temp/build`、项目根 `build/`、`dist/`）

不再生成 `build_report.html`（GUI 时代的产物，脚本直接输出日志即可）。

### 3.2 第二步：持久化并修正 spec

将 spec 固化为 `packaging/NetEaseMusic.spec`：

- **修正 hiddenimports**：补齐 `gui.title_bar`、`gui.window_resize`、`pipewire_manager_integration`
- **路径可移植**：用 `os.path.dirname(os.path.abspath(SPECPATH))` 推导项目根，去掉硬编码
- **裁剪 datas**：
  - `icon/` 只带运行时用到的尺寸（`main.py:78-86` 的加载优先级确认后保留 1-2 个 + AppDir 用的 256）
  - `config/`、`logger/`、`gui/` 是 Python 包，改走 imports 而非 datas 整体拷贝（移除 `__pycache__`）
- **扩充 excludes**（瘦身主力，逐项实测验证）：
  - 现有：tkinter、matplotlib、numpy、scipy、pandas、PIL、cv2
  - 新增候选：`PySide6.Qt3D*`、`PySide6.QtQuick*`（注意 QtWebEngine 依赖 QtQuick，**需实测**，不能盲排）、`PySide6.QtQml`、`PySide6.QtMultimedia`、`PySide6.QtSql`、`PySide6.QtTest`、`PySide6.QtCharts`、`PySide6.QtDataVisualization`、`PySide6.QtBluetooth`、`PySide6.QtPositioning`（QtWebEngine 可能依赖，需实测）、`PySide6.QtSensors`、`PySide6.QtSerialPort`、`PySide6.QtSvg`、`PySide6.QtPdf*`、`PySide6.QtRemoteObjects`、`PySide6.QtScxml`、`PySide6.QtStateMachine`、`PySide6.QtTextToSpeech`、`PySide6.QtVirtualKeyboard`、`PySide6.QtWebChannel`（不用 webchannel 才排，需确认）、`PySide6.QtWebSockets` 等
- 保留 `upx=True`、`console=False`、`optimize=2`

### 3.3 第三步：验证瘦身效果（闭环）

每个候选 exclude 遵循"排除 → 构建 → 运行冒烟 → 对比体积"闭环：

1. 基线：先按现状构建一次，记录 AppImage 体积
2. 逐项（或分组）加入 exclude，重新构建
3. 冒烟验证：AppImage 能启动、窗口正常、能加载网易云网页、标题栏三按钮正常、托盘正常、关闭确认弹窗正常
4. 记录每项的体积变化，失败项回退

### 3.4 第四步：清理与文档

- 删除：`packaging/scripts/packaging_gui.py`、`packaging/scripts/quick_build.sh`、`packaging/scripts/test_build.sh`、`packaging/scripts/check_dependencies.sh`、`packaging/scripts/clean_temp_files.sh`、`packaging/start_packaging_gui.sh`、`packaging/README_GUI.md`、`check_dependencies.py`（仅服务于 GUI 启动器）
- `pack.py`：删除，或改为 10 行内的薄封装（调 `packaging/scripts/build_appimage.sh`）——实施时与用户确认
- `clean_temp_files.sh` 中过期的 `packaging_04/` 引用随删除一并消解
- 更新 `常用命令.md:7-8` 的打包命令
- 更新 `AGENTS.md`（如涉及打包相关约定）
- 归档：`packaging/build_logs/` 历史日志保留不动

## 4. 验收清单

- [ ] 一条命令（如 `bash packaging/scripts/build_appimage.sh`）从干净状态直接产出 AppImage
- [ ] 产物仅 `packaging/dish/网易云音乐桌面版-x86_64.AppImage`，无第二套命名/目录
- [ ] AppImage 体积较 211 MiB 基线明显下降（记录实测值）
- [ ] 冒烟通过：启动、网页加载、自定义标题栏三按钮、托盘、关闭确认弹窗
- [ ] spec 无硬编码绝对路径，hiddenimports 包含全部新模块
- [ ] GUI 相关文件全部删除，`常用命令.md` 已更新
- [ ] 打包机以外目录零写入（临时文件均在项目内，遵循 AGENTS.md）

## 5. 风险与注意点

| 风险 | 应对 |
|---|---|
| 过度 exclude 导致 QtWebEngine 运行时报缺模块 | 每项 exclude 单独冒烟验证；重点盯 QtQuick/QtQml/QtPositioning/QtWebChannel |
| UPX 压缩个别 so 后启动失败 | 冒烟失败时对该模块 `upx_exclude` |
| appimagetool 需联网下载 | 保留 `packaging/temp/` 现有副本，脚本不强制重新下载 |
| 删 GUI 后依赖检查能力丢失 | 脚本内保留最小检查（`.venv`、pyinstaller、appimagetool 存在性） |

## 6. 不实施项

- ❌ 不打包其他格式（deb/rpm/zip 等均不考虑）
- ❌ 不做 CI/CD 自动化
- ❌ 不改动 `main.py` 及业务代码（spec 侧适配代码，而非反过来）
- ❌ 不清理 `packaging/build_logs/` 历史日志
- ❌ 不处理 quick 版旧产物名 `NetEaseCloudMusic` 的历史遗留（随模式删除自然消解）
