# 桌面图标链路 3 修复计划

## 一、问题背景

打包出的 AppImage 在运行时任务栏 / 最小化后的任务栏项显示系统默认「齿轮」图标，而非自定义图标。

按通用指南，Linux 桌面图标由三条独立链路组成，断任何一条即退回齿轮。经代码审计，三条链路现状如下：

| 链路 | 现状 | 结论 |
|------|------|------|
| 1 代码内窗口图标 | `main.py:97` 已调 `app.setWindowIcon()`，但只注册**单张** 48×48 图（首个命中即 break），非多尺寸注册 | 基本可用，有糊边隐患，顺带改进 |
| 2 desktop 文件 + 图标文件 | `packaging/scripts/build_appimage.sh:52-66` 已在 AppDir 根生成 `netease-music-desktop.desktop`（`Icon=netease-music-desktop`）与 `netease-music-desktop.png`，命名逐字一致 | ✅ 合规 |
| 3 StartupWMClass 关联 | desktop 文件已写 `StartupWMClass=netease-music-desktop`（build_appimage.sh:65），代码已调 `setDesktopFileName`（main.py:110），**但缺两个关键动作**（见下） | ❌ **根因所在** |

## 二、根因分析（链路 3）

指南 §四「X11 深坑」：WM_CLASS 由 instance、class 两个字段组成，二者来源不同，必须分别钉死。当前代码两个都漏了：

1. **缺 `setApplicationName()`** —— 全项目未调用（grep 已确认）。WM_CLASS 的 class 字段无显式来源，Qt 回退到从 `argv[0]` 推导。
2. **未在 `QApplication` 创建前改写 `sys.argv[0]`** —— `main.py:66` 直接 `QApplication(sys.argv)`。instance 字段取 `argv[0]` 主名，随打包形态漂移：
   - AppImage 经 AppRun 启动时：`argv[0]` 主名为 `NetEaseMusicDesktop`；
   - 用户直接双击 AppImage 时：主名为 `网易云音乐桌面版-x86_64`（含中文与后缀）。

两种形态下窗口实际 WM_CLASS 都与 desktop 文件的 `StartupWMClass=netease-music-desktop` **失配**，桌面环境无法把运行窗口关联到 desktop 文件，任务栏取不到图标 → 齿轮。与用户经验判断一致。

## 三、修复方案

### 阶段 1：诊断确认（命令行，无需视觉）

运行当前 AppImage（或开发态 `.venv/bin/python main.py`），用命令行实测窗口 WM_CLASS 双字段：

```bash
# 列出所有窗口的 WM_CLASS，定位本应用窗口的实际值
xprop -root _NET_CLIENT_LIST  # 取窗口 id 列表
# 或交互式：xprop WM_CLASS 后点击窗口
```

- 预期实测值 ≠ `netease-music-desktop`（证实失配）；
- 若实测值恰好已是 `netease-music-desktop`，则根因不在链路 3，需回头重查（暂停实施，上报用户）。

### 阶段 2：代码修复（`main.py`）

在 `QApplication` 创建**之前**与之后各加一个动作：

```python
sys.argv[0] = "netease-music-desktop"   # QApplication 创建前，钉死 WM_CLASS instance
app = QApplication(sys.argv)
app.setApplicationName("netease-music-desktop")  # 钉死 WM_CLASS class
app.setDesktopFileName("netease-music-desktop")  # 已有（main.py:110），保留
```

要点：

- `sys.argv[0]` 改写必须早于 `QApplication(sys.argv)`，晚则无效；
- 三处字符串与 desktop 文件 `StartupWMClass` 值**逐字一致**：`netease-music-desktop`；
- 顺带改进链路 1：将 `main.py` 图标注册由「单张图首个命中即 break」改为**多尺寸注册**（`QIcon.addFile()` 收编 `icon/` 下全部 7 个尺寸），消除糊边隐患；`gui/main_window.py:109-118` 同款逻辑保持最小改动，仅在窗口图标为单图导致任务栏仍有异常时再处理。

### 阶段 3：打包核验

1. 执行 `bash packaging/scripts/build_appimage.sh` 重新构建 AppImage；
2. 冒烟验证：`--appimage-extract` 解包产物，断言 `netease-music-desktop.desktop` 与 `netease-music-desktop.png` 均在包内（链路 2 回归确认）；
3. 命令行复测 WM_CLASS：运行新 AppImage，`xprop` 实测双字段应**均等于** `netease-music-desktop`。

### 阶段 4：人工视觉验证（用户执行）

视觉验证不由 AI 执行。阶段 3 通过后，**通过选项框通知用户**，请用户确认以下各项是否已显示自定义图标：

- 窗口标题栏
- 任务栏（含最小化后）
- Alt-Tab 切换器
- 应用菜单 / 启动器

用户反馈未修复的项 → 回到对应链路重查；全部通过 → 收尾归档。
