# 文档编写规范

> **版本**：v3.1 — 强制约束型
> **适用范围**：`文档/` 目录及子目录 `.md`；根目录技术报告 `.md`
> **生效日期**：2026-07-24

---

## 1. 时区基准

全文档所有时间字段基准时区为 **UTC+8（Asia/Taipei）**。

---

## 2. 命名

### 2.1 格式表

| 对象 | 格式 | 示例 |
|:---|:---|:---|
| 文件 | `YYYY-MMDD-HHMM_文档标题.md`，中文优先，英文名后置 | `2026-0709-0328_升级输入维度与重叠特征_STDP网络压力测试计划.md` |
| 目录 | 中文，无日期前缀 | `work plans/`、`文档/`、`work charter/` |
| 根目录 `.md` | 同文件格式 | `2026-0709-0328_示例技术报告.md` |

### 2.2 文件名格式说明

| 字段 | 格式 | 说明 |
|:---|:---|:---|
| `YYYY` | 4 位年份 | 例如 `2026` |
| `MMDD` | 2 位月份 + 2 位日期 | 无分隔符，例如 `0709` |
| `HHMM` | 2 位小时 + 2 位分钟 | 24 小时制，无分隔符，例如 `0328`；无分钟时用 `00` |
| `_` | 下划线 | 分隔时间戳与标题 |
| `文档标题` | 中文优先 | 可包含英文缩写，例如 `STDP网络压力测试计划` |
| `.md` | 扩展名 | Markdown 格式 |

### 2.3 错误示例

| 错误写法 | 问题 |
|:---|:---|
| `2026-07-09-14_文档标题.md` | 月份与日期之间、小时前使用了连字符分隔，不符合紧凑格式 |
| `2026-0709-14_文档标题.md` | 分钟未补零，应为 `1400` |
| `2026-07-09_文档标题.md` | 缺少时间戳 `HHMM` |

## 3. 头部元信息

### 3.1 模板

```markdown
> **状态**：草稿 / 已实施 / 已归档 / 待验证 / 已确认
> **范围**：影响的模块或范围
> **时间**：YYYY-MM-DD HH:MM（设计）/ YYYY-MM-DD HH:MM（实施）
> **优先级**：高 / 中 / 低（可选）
```

时间首次标注 `(UTC+8)`，后续省略。设计时间作为文件命名依据，取其 `HHMM` 紧凑格式。

### 3.2 归档声明

`文档/` 目录下文档，标题后、元信息前插入：

```markdown
> **⚠️ 归档状态**：本文档撰写于 YYYY-MMDD-HHMM，记录当时的实施状态。
> 文档中提及的"已知问题"和"待办项"可能已在后续修复，请勿以本文档推断当前代码。
```

时间精确匹配文件名 `YYYY-MMDD-HHMM`（无分钟则用 `00`），措辞固定，禁止改写。

## 4. 代码与文件引用

| 场景 | 要求 |
|:---|:---|
| 代码块 | 首行标注 `# 文件路径` |
| 文件引用 | 见 §4.1 唯一性判据，一律反引号纯文本，❌ **禁止** Markdown 链接 `[](path)` |
| 行号 | 🔴 **禁止标注** |

### 4.1 文件引用格式：唯一性判据

判据为 **全局唯一性**：带标准时间戳 `YYYY-MMDD-HHMM_` 的文档默认视为唯一。

| 情形 | 写法 | 示例 |
|:---|:---|:---|
| 全局唯一（含带时间戳文档） | 仅文件名 | `2026-0721-0825_阶段1服务端实现计划.md` |
| 可能重名（`README`、无时间戳文档、代码文件等） | 项目根相对路径 | `Zen_VocoType_Service/src/zen_vocotype_service/config.py`、`文档/提示语句/文档编写规范.md` |
| 带时间戳却罕见重名 | 回退项目根相对路径 | `work plans/2026-0701-0900_同名计划.md`（假设场景） |

规则要点：

- **一律反引号纯文本**，不制作可点击 Markdown 链接；AI 落地读取仅文件名时用 `**/<文件名>` glob 兜底定位。
- 设计目标：带时间戳引用对「引用方移动」与「被引用方移动」双免疫；代码与规范类文件以项目根路径精确锚定，消除同名歧义。
- 禁止沿用 v2.x 的 `` [`path`](path) `` 链接写法。

## 附录：AI 时间获取

AI 无实时时钟，严禁臆造。

### 正确做法

**首选：shell 命令强制时区取值。** 必须使用 `TZ=Asia/Taipei` 前缀，禁止省略：

```bash
TZ=Asia/Taipei date '+%Y-%m-%d %H:%M'
```

`TZ=` 前缀将本次调用的时区强制锁定为 UTC+8，与系统时区配置无关，可彻底避免误拿 +0 时区。

**健壮性校验（首次使用或跨会话时执行一次）：**

```bash
timedatectl
```

确认输出中 `System clock synchronized: yes`。若命令不存在或显示未同步，说明本机时钟不可信，回退到网络 API。

**回退：网络时间 API**（仅在校验失败或 shell 不可用时使用）：

| | |
|:---|:---|
| 主 API | `https://timeapi.io/api/Time/current/zone?timeZone=Asia/Taipei` |
| 备用 API | `https://worldtimeapi.org/api/timezone/Asia/Taipei` |
| 提取字段 | `dateTime` |

失败处理：先切备用 API，仍失败则向用户索要时间。

### 禁止做法

**禁止裸用 `date`（不带 `TZ=` 前缀）获取当前时间。** 裸 `date` 跟随系统时区配置，系统时区为 UTC 时会拿到 +0 时区时间，导致与 UTC+8 差 8 小时。

例如以下命令都是 **错误** 的，不可使用：

```bash
# 错误：跟随系统时区，系统时区为 UTC 时输出 +0 时区
date '+%Y-%m-%d %H:%M'

# 错误：-u 强制输出零时区
date -u '+%Y-%m-%d %H:%M'

# 错误：-d 参数格式无效，TZ="Asia/Taipei" 不是合法日期字符串，会回退到系统时区
date '+%Y-%m-%d %H:%M' -d 'TZ="Asia/Taipei"'
```

### 常见错误示例

| 错误写法 | 问题 |
|:---|:---|
| `date '+%Y-%m-%d %H:%M'` | 未指定时区，跟随系统配置；系统时区为 UTC 时拿到 +0 时区，比 UTC+8 慢 8 小时。 |
| `date -u '+%Y-%m-%d %H:%M'` | `-u` 强制输出零时区，必然与 UTC+8 差 8 小时。 |
| `date '+%Y-%m-%d %H:%M' -d 'TZ="Asia/Taipei"'` | `-d` 参数解析失败，实际回退到系统默认时区或 UTC，导致时间/小时错误。 |
