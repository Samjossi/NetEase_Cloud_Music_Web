
# 配置治理通用协议 v1.0

> **协议类型**：工程规范 / 可交付实施文档  
> **版本**：v1.0  
> **适用范围**：任何使用「dataclass + TOML」模式的 Python 项目配置系统  
> **制定依据**：V1 引擎 10 份历史治理文档的实践经验验证  
> **强制性**：本协议中所有以「必须」「禁止」开头的条款为强制性规范，以「建议」「可以」开头的条款为推荐性规范  

---

## 一、术语定义

| 术语 | 定义 |
|------|------|
| **Config 类** | 使用 `@dataclass` 定义的参数容器类，负责声明全部可调参数及其默认值 |
| **根配置 (Root Config)** | 项目入口级 TOML 文件（如 `configs/engine.toml`），聚合各子系统预设引用 |
| **预设 (Preset)** | 子系统级 TOML 文件（如 `configs/module_presets/*.toml`），包含具体参数值 |
| **配置消费链路** | 参数从「TOML 文件 → Config 类 → 算法模块 → 算法逻辑」的完整传递路径 |
| **僵尸参数** | 在 Config 类中声明、在预设中存在，但算法逻辑中**从未被读取**的参数 |
| **回退污染** | 使用 `dict.get(key, default)` 模式，参数缺失时静默使用默认值，导致配置行为不可预测 |
| **伪可配置参数** | 在 Config 类中声明、在预设中存在，算法逻辑中虽有读取但**读取后不使用**或**使用但不影响输出**的参数 |
| **硬编码参数** | 直接以字面量形式写在算法代码中的数值，未经 Config 系统管理 |

## 二、核心规则（强制性）

### 规则 1：配置定义必须与算法消费严格一致

**规范**：
- **必须**：每个在 Config 类中声明的参数，必须在算法逻辑中有明确的消费点。
- **禁止**：Config 类中声明了参数，但算法模块的 `process()` / `compute()` 函数不接收、不读取该参数。
- **必须**：算法模块的入口函数必须通过参数显式接收 Config 对象（或相关字段），禁止在模块内部使用与配置同名的局部变量覆盖配置值。

**正确示例**：
```python
# config.py
@dataclass
class EngineConfig:
    corner_threshold: float = 0.3
    corner_min_dist: int = 3

# corner.py
# ✅ 正确：接收 cfg，使用 cfg 中的值
def process(features: dict, cfg: EngineConfig) -> dict:
    threshold = cfg.corner_threshold      # 来自配置
    min_dist = cfg.corner_min_dist        # 来自配置
    ...
```

**错误示例**：
```python
# corner.py
# ❌ 错误：函数签名硬编码，完全不消费配置
def process(features: dict, threshold: float = 0.3, min_dist: int = 3) -> dict:
    ...
```

---

### 规则 2：禁止回退污染链

**规范**：
- **禁止**：在配置加载代码中使用 `data.get("key", default_value)` 模式加载核心参数。
- **必须**：核心参数缺失时，立即抛出异常并终止程序运行。
- **必须**：所有核心参数必须在预设文件中显式声明，不能依赖 dataclass 默认值兜底。
- **可以**：仅对「可选参数」使用 `.get(key, default)`，但必须在文档中明确标注该参数为可选。

**正确示例**：
```python
# ✅ 正确：核心参数缺失时立即报错
def require(data: dict, key: str) -> Any:
    if key not in data:
        raise ConfigError(f"缺少必需配置参数: {key}")
    return data[key]

# config.py
@classmethod
def from_toml(cls, path: Path) -> "EngineConfig":
    with open(path, "rb") as f:
        data = tomllib.load(f)
    module = data.get("module", {})
    return cls(
        threshold=require(module, "threshold"),   # 缺失时报错
        min_dist=require(module, "min_dist"),     # 缺失时报错
        verbose=module.get("verbose", False),     # 可选参数，可以兜底
    )
```

**错误示例**：
```python
# ❌ 错误：静默使用默认值，用户完全无感知
return cls(
    threshold=module.get("threshold", 0.3),   # 缺失时静默用 0.3
    min_dist=module.get("min_dist", 3),       # 缺失时静默用 3
)
```

---

### 规则 3：预设文件必须完整覆盖全部可调参数

**规范**：
- **必须**：子系统的全部可调参数必须在对应的预设文件中显式声明，不能部分在预设、部分在根配置中"兜底"。
- **禁止**：根配置文件中直接定义子系统的具体参数值（根配置只负责引用预设文件路径和开关类参数）。
- **必须**：新增参数时，所有预设文件必须同步更新。

**正确示例**：
```toml
# configs/corner_presets/默认参数.toml
name = "默认参数"
description = "标准角点检测配置"

[params]
threshold = 0.3
min_dist = 3
window_size = 7
use_nms = true
```

**错误示例**：
```toml
# ❌ 错误：预设中只写了 1 个参数，其余在根配置中兜底
# configs/corner_presets/默认参数.toml
[params]
threshold = 0.3

# configs/engine.toml
[engine]
# 根配置不应该兜底子系统参数
corner_min_dist = 3
corner_window_size = 7
```

---

### 规则 4：配置归属与物理位置一致

**规范**：
- **必须**：参数的 Config 类归属、预设文件位置、算法消费位置三者必须一致。
- **禁止**：在 A 模块的 Config 中声明参数，但由 B 模块的 Config 负责运行时传递。
- **必须**：跨模块共享的参数必须在根配置中统一声明一次，各模块通过同一个 Config 对象引用。

**正确示例**：
```python
# 共享参数在根配置中统一声明
# config.py
@dataclass
class EngineConfig:
    gauss_sigma: float = 2.0          # 被 corner 和 curvature 共用

# corner.py
# ✅ 正确：从统一的 cfg 中读取
def process(features, cfg: EngineConfig):
    sigma = cfg.gauss_sigma

# curvature.py
# ✅ 正确：从同一个 cfg 中读取
def process(features, cfg: EngineConfig):
    sigma = cfg.gauss_sigma
```

**错误示例**：
```python
# ❌ 错误：corner 的参数由 curvature_config 管理
def run_pipeline(config):
    corner.process(
        features,
        sigma=config.curvature.gauss_sigma,   # 配置归属错位
    )
```

### 规则 5：跨模块依赖必须透明化 + 一致性校验

**规范**：
- **必须**：如果一个参数被多个模块消费，必须在根配置中统一声明。
- **必须**：根配置的 `from_toml()` 方法中必须包含跨模块一致性校验逻辑。
- **禁止**：允许两个模块消费同名参数但取值不同的情况发生。

**正确示例**：
```python
# config.py
@dataclass
class EngineConfig:
    shared_sigma: float = 2.0

    def validate(self):
        """跨模块一致性校验"""
        if self.shared_sigma <= 0:
            raise ConfigError("shared_sigma 必须大于 0")

# 根配置加载时自动校验
@classmethod
def from_toml(cls, path: Path) -> "EngineConfig":
    cfg = cls(...)  # 解析逻辑
    cfg.validate()   # 强制校验
    return cfg
```

### 规则 6：僵尸参数零容忍

**规范**：
- **禁止**：Config 类中存在算法逻辑不消费的参数。
- **禁止**：预设文件中存在算法逻辑不消费的参数。
- **必须**：每次算法重构后，必须同步执行配置系统清理。
- **必须**：对疑似僵尸参数执行「逆向链路审计」——在算法逻辑中全文检索参数名的消费位置。

**处理流程**：
1. 发现疑似僵尸参数 → 在算法代码中全文检索参数名
2. 确认无任何消费点 → 标记为僵尸参数
3. 从 Config 类中删除该字段
4. 从所有预设文件中删除该键
5. 从根配置解析逻辑中删除该字段
6. 从 pipeline/调用代码中删除该参数传递

---

### 规则 7：硬编码参数必须分类标记

**规范**：
- **必须**：所有硬编码数值必须在代码中添加分类标记注释。
- **必须**：分类体系必须包含以下五类：
  - 🟢 **生理锚定**：基于生物系统实验数据的固定常数，**禁止修改**
  - 🔵 **工程稳定**：数值稳定性常数（epsilon、除零保护等），**禁止修改**
  - 🟡 **算法常数**：影响输出质量的经验常数，**低优先级可配**
  - 🟠 **可视化参数**：仅影响展示不影响计算，**可配**
  - ⚪ **派生常量**：由 TOML 参数数学推导而来，**不应直接修改**
- **建议**：定期（每季度）扫描全代码库硬编码参数，产出分类报告。

**正确示例**：
```python
# 🟢 生理锚定：哺乳动物 LGN 半响应对比度常数 c50
# 参考文献：Geisler & Albrecht (1997)
# 禁止修改，除非进行特殊生理学研究
alpha: float = 0.3

# 🔵 工程稳定：除法归一化分母偏移，防止除零
# 属于数值计算通用技巧，无需暴露给用户
epsilon: float = 1e-4

# 🟡 算法常数：中心差分除数
# 影响梯度幅值，极低分辨率图像可尝试改为 1.0（前向差分）
gradient_divisor: float = 2.0
```

---

### 规则 8：配置治理必须工具化 + CI 化

**规范**：
- **必须**：项目必须包含预设文件验证工具，检查项包括：
  - 参数缺失检查
  - 类型错误检查
  - 废弃参数残留检查
  - 跨模块一致性检查
- **必须**：预设验证必须在 CI 中强制执行，不合规的预设文件提交必须被阻止。
- **建议**：提供预设迁移工具，自动为旧预设添加缺失参数、移除废弃参数。

**验证工具最小功能清单**：
```python
def validate_preset(preset_path: Path, required_params: set[str]) -> list[str]:
    """验证单个预设文件
    
    返回发现的错误列表，空列表表示验证通过。
    """
    errors = []
    data = load_toml(preset_path)
    params = data.get("params", {})
    
    # 检查必需参数
    missing = required_params - set(params.keys())
    if missing:
        errors.append(f"缺少必需参数: {missing}")
    
    # 检查废弃参数
    deprecated = {"old_param_name", "zombie_param"}
    found_deprecated = deprecated & set(params.keys())
    if found_deprecated:
        errors.append(f"包含废弃参数: {found_deprecated}")
    
    return errors
```

## 三、实施阶段（标准流程）

### 阶段 1：链路修复（紧急）

**目标**：修复配置定义了但算法不消费的问题。

**输入**：现有 Config 类、算法模块、预设文件  
**输出**：所有算法模块的 `process()` / `compute()` 函数正确消费 Config 参数  
**耗时**：1-2 天  

**步骤清单**：
- [ ] 列出 Config 类中声明的全部参数
- [ ] 对每个算法模块，检查其 `process()` 函数是否接收 Config 对象
- [ ] 对每个参数，在算法逻辑中确认消费位置
- [ ] 修改 `process()` 函数签名，增加 `cfg: Config` 参数
- [ ] 修改 pipeline/调度代码，调用时传入 `cfg`
- [ ] 修改算法逻辑，使用 `cfg.xxx` 替代硬编码值
- [ ] 运行单元测试，确认行为一致

**验收标准**：
> 任意一个 Config 参数的值被修改后，算法输出必须发生相应变化。如果修改参数后输出不变，说明该参数未被消费，链路修复未完成。

---

### 阶段 2：全链路审计（系统性）

**目标**：产出「参数全链路审计报告」，标记所有僵尸参数、伪可配置参数、回退污染点。

**输入**：全部 Config 类、全部算法模块、全部预设文件  
**输出**：审计报告文档 + 问题清单  
**耗时**：1-2 天  

**审计表格模板**：

| 参数名 | Config 声明？ | TOML 声明？ | `process()` 接收？ | 算法消费？ | 问题标记 |
|--------|:------------:|:----------:|:-----------------:|:---------:|:-------:|
| `threshold` | ✅ | ✅ | ✅ | ✅ | — |
| `min_dist` | ✅ | ✅ | ❌ | ❌ | 🔴 链路断裂 |
| `old_param` | ✅ | ❌ | ❌ | ❌ | 🔴 僵尸参数 |
| `reserved` | ✅ | ✅ | ✅ | ❌ | 🟡 伪可配置 |

**步骤清单**：
- [ ] 正向链路审计：TOML → Config → process() → 算法逻辑
- [ ] 逆向链路审计：算法逻辑 → 检索每个配置参数名的消费位置
- [ ] 标记僵尸参数（声明但零消费）
- [ ] 标记伪可配置参数（声明也消费但消费后不影响输出）
- [ ] 标记回退污染点（`.get(key, default)` 模式）
- [ ] 标记跨模块依赖参数

---

### 阶段 3：清理与规范化（修复）

**目标**：消除审计发现的所有问题。

**输入**：阶段 2 产出的问题清单  
**输出**：干净的配置系统 + 更新后的预设文件  
**耗时**：1-2 天  

**步骤清单**：
- [ ] 删除所有僵尸参数（Config 类、预设文件、pipeline 代码）
- [ ] 将 `.get(key, default)` 改为 `require()` 或显式读取
- [ ] 补充缺失的预设参数到所有预设文件
- [ ] 补充缺失的 TOML 节到根配置文件
- [ ] 修改 Config 类的 `from_toml()`，补充缺失字段的解析
- [ ] 为硬编码参数添加分类标记注释
- [ ] 运行全部测试，确认无回归

---

### 阶段 4：工具化与 CI 集成（可持续）

**目标**：让配置治理自动化，不依赖人工审查。

**输入**：规范化后的配置系统  
**输出**：验证工具 + CI 配置  
**耗时**：0.5-1 天  

**步骤清单**：
- [ ] 创建 `preset_validator.py`，实现参数缺失/类型/废弃参数检查
- [ ] 创建 `preset_migrator.py`，实现旧预设自动迁移
- [ ] 在 CI 配置（如 `.github/workflows/ci.yml`）中集成预设验证
- [ ] 添加提交前钩子（pre-commit），本地拦截不合规预设
- [ ] 编写配置系统 README，文档化所有参数含义和来源

## 四、代码规范模板

### 4.1 Config 类标准模板

```python
from dataclasses import dataclass, fields
from pathlib import Path
from typing import Any

try:
    import tomllib
except ImportError:
    import tomli as tomllib  # type: ignore


class ConfigError(Exception):
    """配置错误，参数缺失或类型错误时抛出。"""
    pass


def require(data: dict[str, Any], key: str) -> Any:
    """强制要求参数存在，缺失时立即报错。"""
    if key not in data:
        raise ConfigError(f"❌ 缺少必需配置参数: '{key}'。请在预设文件中显式声明。")
    return data[key]


@dataclass
class ModuleConfig:
    """子系统配置模板。
    
    所有核心参数必须在预设文件中显式声明，禁止依赖默认值兜底。
    """
    # 核心参数（缺失时报错）
    threshold: float
    window_size: int
    
    # 可选参数（可以兜底）
    verbose: bool = False
    
    @classmethod
    def from_toml(cls, path: Path) -> "ModuleConfig":
        with open(path, "rb") as f:
            data = tomllib.load(f)
        
        params = data.get("params", {})
        
        return cls(
            threshold=require(params, "threshold"),      # 核心参数：缺失报错
            window_size=require(params, "window_size"),  # 核心参数：缺失报错
            verbose=params.get("verbose", False),         # 可选参数：可以兜底
        )
    
    def validate(self) -> None:
        """参数合理性校验，在 from_toml() 末尾自动调用。"""
        if self.threshold < 0 or self.threshold > 1:
            raise ConfigError(f"threshold 必须在 [0, 1] 范围内，当前为 {self.threshold}")
        if self.window_size % 2 == 0:
            raise ConfigError(f"window_size 必须为奇数，当前为 {self.window_size}")


@dataclass
class EngineConfig:
    """根配置模板。
    
    负责聚合各子系统配置，并执行跨模块一致性校验。
    """
    module: ModuleConfig
    shared_sigma: float = 2.0
    
    @classmethod
    def from_toml(cls, path: Path) -> "EngineConfig":
        with open(path, "rb") as f:
            data = tomllib.load(f)
        
        root = data.get("engine", {})
        module_preset = Path(path).parent / root.get("module_preset", "module_presets/default.toml")
        
        cfg = cls(
            module=ModuleConfig.from_toml(module_preset),
            shared_sigma=root.get("shared_sigma", 2.0),
        )
        cfg.validate()
        return cfg
    
    def validate(self) -> None:
        """跨模块一致性校验。"""
        if self.shared_sigma <= 0:
            raise ConfigError("shared_sigma 必须大于 0")
```

### 4.2 算法模块标准模板

```python
import numpy as np
from config import EngineConfig


def process(features: dict[str, np.ndarray], cfg: EngineConfig) -> dict[str, np.ndarray]:
    """算法处理函数模板。
    
    必须接收 cfg 参数，并从中读取配置值。禁止在函数内部定义与配置同名的局部变量。
    """
    # ✅ 正确：从 cfg 读取配置值
    threshold = cfg.module.threshold
    window_size = cfg.module.window_size
    
    # 算法逻辑...
    result = features["input"] * threshold  # 示例
    
    return {"output": result}
```

### 4.3 Pipeline 调用标准模板

```python
from config import EngineConfig
from corner import process as corner_process
from contour import process as contour_process


class EngineProcessor:
    def __init__(self, cfg: EngineConfig):
        self.cfg = cfg
    
    def process(self, features: dict) -> dict:
        # ✅ 正确：将 cfg 传递给每个子模块

            "corner": corner_result,
```

### 4.5 预设验证工具标准模板

```python
"""预设文件验证工具模板。"""

from pathlib import Path
from typing import Set, Dict, List
import tomllib


class PresetValidator:
    """预设文件完整性验证器。"""
    
    def __init__(self, configs_dir: Path):
        self.configs_dir = Path(configs_dir)
    
    def validate_module(self, preset_dir: Path, required: Set[str], deprecated: Set[str] = None) -> List[str]:
        """验证单个预设目录。"""
        errors = []
        deprecated = deprecated or set()
        
        for preset_file in preset_dir.glob("*.toml"):
            if preset_file.name == "README.md":
                continue
            
            try:
                with open(preset_file, "rb") as f:
                    data = tomllib.load(f)
                
                params = data.get("params", {})
                
                # 检查必需参数
                missing = required - set(params.keys())
                if missing:
                    errors.append(f"🔴 {preset_file.name}: 缺少必需参数 {missing}")
                
                # 检查废弃参数
                found_deprecated = deprecated & set(params.keys())
                if found_deprecated:
                    errors.append(f"🟡 {preset_file.name}: 包含废弃参数 {found_deprecated}")
                    
            except Exception as e:
                errors.append(f"❌ {preset_file.name}: 解析失败 - {e}")
        
        return errors
    
    def validate_all(self) -> Dict[str, List[str]]:
        """验证所有预设目录。"""
        results = {}
        
        # 示例：验证 corner 预设
        results["corner"] = self.validate_module(
            self.configs_dir / "corner_presets",
            required={"threshold", "window_size"},
            deprecated={"old_param"}
        )
        
        return results


def main():
    validator = PresetValidator(Path("configs"))
    results = validator.validate_all()
    
    total = sum(len(e) for e in results.values())
    if total == 0:
        print("✅ 所有预设文件验证通过")
        return 0
    
    print(f"❌ 发现 {total} 个问题：")
    for module, errors in results.items():
        if errors:
            print(f"\n【{module}】")
            for err in errors:
                print(f"  - {err}")
    return 1


if __name__ == "__main__":
    exit(main())
```

## 六、常见反模式与修正方法

| 反模式 | 症状 | 根因 | 修正方法 |
|--------|------|------|---------|
| **配置真空** | 修改 TOML 参数后输出完全不变 | 算法模块不消费 Config | 修改 `process()` 接收 `cfg`，用 `cfg.xxx` 替代硬编码 |
| **回退污染** | 删除 TOML 参数后程序仍能运行 | 使用 `.get(key, default)` | 改为 `require()`，缺失时报错 |
| **僵尸参数** | TOML 中有参数但算法输出不受影响 | 算法重构后未清理配置 | 逆向审计 → 确认零消费 → 从全链路删除 |
| **配置错位** | 在 A 预设中调参但影响 B 模块 | 参数归属与消费位置不一致 | 将参数移至正确的 Config 类，更新传递链路 |
| **根配置兜底** | 子系统参数分散在根配置和预设中 | 预设不完整 | 将所有子系统参数移至预设文件，根配置只留引用路径 |
| **硬编码黑洞** | 大量可调参数直接写在算法代码中 | 未纳入配置系统 | 将参数提取到 Config 类，算法通过 `cfg` 读取 |
| **伪可配置** | 参数被读取但读取后不使用 | 预留参数未实现 / 算法剪枝 | 确认是否为预留接口：是则标注文档，否则删除 |

## 七、验收标准

配置治理实施完成后，必须满足以下全部条件方可验收：

1. **参数修改响应性**：修改任意一个 TOML 预设参数的值后，对应算法模块的输出必须发生可观测的变化。如果修改参数后输出不变，说明链路断裂，验收不通过。

2. **参数缺失报错性**：从任意一个预设文件中删除一个核心参数后，程序在启动/加载配置时必须抛出异常并终止，不能静默使用默认值运行。

3. **预设完整性**：所有预设文件包含的参数集合完全一致（仅值不同），不存在某个预设缺少其他预设拥有的核心参数。

4. **零僵尸参数**：Config 类中声明的全部参数在算法逻辑中都有消费点；预设文件中存在的全部参数在 Config 类中都有声明。

5. **工具通过**：运行 `preset_validator.py` 后输出 `✅ 所有预设文件验证通过`，无任何错误。

6. **测试通过**：全部现有单元测试和集成测试通过，无功能退化。
